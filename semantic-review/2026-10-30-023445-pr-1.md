# Security and reliability boundary fixes for NEXUS completion

This follow-up addresses the original provider-wire, budget, GitHub concurrency, backup authenticity, deletion, CSRF, discovery, input-boundary, streaming, and runtime-package findings. Per-provider schema translation, dispatch-time accounting, conditional GitHub claims, authenticated backup manifests, validation fencing, shared mutation checks, bounded streams, and production-only runtime dependencies now cover most of the release boundary. Owner quiescence remains incomplete for credentialed GitHub work, and two provider normalization paths still violate their stated limits or local-schema contract.

**Watch for:** **confirmed** GitHub requests can use a decrypted owner token and write after account deletion completes, **confirmed** OpenAI strict structured responses reject nullable representations of optional local fields, and **confirmed** Gemini checks each tool-argument chunk but not the merged call.

**Verdict**: NEEDS_CHANGES

## High-level view

Most original blockers now have boundary-level fixes and focused regressions. Dispatch-time accounting, authenticated manifests, conditional GitHub claims, shared mutation checks, complete fenced discovery, byte limits, and production-only runtime packaging replace the earlier fail-open paths.

**confirmed**: owner quiescence tracks chat, research-model, agent, provider-validation, and GitHub-connection operations in one process, but ordinary authenticated GitHub operations are outside that registry. Those operations decrypt the token once and continue without a deletion-linked abort signal, so deletion can remove the owner and intent rows while an external write is still pending. Research connector work also starts before registration, and evidence-only research is never registered.

**confirmed**: OpenAI wire translation correctly makes optional tool fields required-and-nullable and removes returned nulls before tool validation. The same translation is used for strict structured output, but that response path validates the provider's null directly against the canonical optional field and rejects it.

**confirmed**: all adapters bound frames, streams, generated text, and most tool arguments before parsing. Gemini can merge repeated `functionCall` objects under one provider ID without checking the serialized merged value, which bypasses the advertised per-call argument ceiling while remaining under the larger stream ceiling.

1. **GitHub calls escape owner quiescence** — **confirmed:** token-bearing GitHub operations are not registered or aborted, so a pending write can execute after account deletion completes. Register all authenticated GitHub calls before token decryption and drain them through durable reconciliation.
2. **Research admission starts before quiescence registration** — **confirmed:** connector retrieval begins before the owner operation, and evidence-only research never registers. Fence and register every research admission before connector dispatch.
3. **OpenAI optional response nulls fail local validation** — **confirmed:** strict wire schemas make optional response fields nullable, but the response path validates those nulls against the non-null canonical schema. Remove wire-only nulls before exact canonical validation and add nested optional response fixtures.
4. **Gemini merged tool arguments exceed the per-call cap** — **confirmed:** each chunk is bounded before repeated chunks are merged, but the merged call is not. Bound the serialized merged candidate before assignment and test chunked aggregate overflow.

## Owner deletion does not drain credentialed GitHub operations

**confirmed**: `tokenFor` checks owner state and decrypts the GitHub token once (`src/modules/github/service.ts:108-113`), but branch creation, file application, and pull-request creation do not register an owner operation (`src/modules/github/service.ts:371`, `448`, `524`). After any write function passes `tokenFor`, it can await preflight reads and later POST or PUT with the captured token while `quiesceOwner` sees no active operation, deletes the credential and user, and reports completion. The intent row can disappear in the account cascade before the external effect returns. Only initial GitHub connection setup uses `beginOwnerOperation` (`src/modules/github/service.ts:231-234`).

**confirmed**: research admission has a smaller version of the same gap. Connector retrieval starts at `src/modules/research/service.ts:229`, while registration begins only at line 264 and only when a model target exists. Evidence-only research and pre-model retrieval can therefore continue after deletion begins instead of being blocked or drained.

The new deletion regression manually registers operations named `chat`, `research`, `agent`, and `delegated_agent` (`tests/integration/account-deletion.test.ts:168-172`); it does not execute those production paths or any GitHub call. Register every credentialed/external operation before decryption or network dispatch, combine its controller with request deadlines, and keep the operation registered through durable reconciliation. Move research admission ahead of connector dispatch, including evidence-only runs, and replace the synthetic test with synchronized production-path tests that prove no provider or GitHub request can execute after deletion completes.

## OpenAI optional structured fields are nullable only on the wire

**confirmed**: strict response schemas pass through `openAIStrictWireSchema` (`src/modules/gateway/adapters/openai-compatible.ts:59-62`), which correctly represents a locally optional string as `type: ["string", "null"]`. Tool calls remove those wire-only nulls before returning canonical arguments (`src/modules/gateway/adapters/openai-compatible.ts:120-122`), but structured responses go directly to `parseStructuredOutput` with the canonical schema (`src/modules/gateway/adapters/openai-compatible.ts:124`). A targeted review-time reproduction emitted `{ "requiredValue": "yes", "optionalValue": null }` under the translated strict schema and received `Provider returned structured output that did not match the requested schema.`

Normalize wire-only nulls against the canonical response schema before exact local validation, using the same recursive omission rule as tool arguments. Add a strict structured-output fixture with optional nested object and array fields so local optionality and explicit canonical nullability remain distinguishable.

## Gemini merges tool arguments past the per-call ceiling

**confirmed**: Gemini bounds each serialized `fn.args` object at 256,000 bytes and then shallow-merges it into a prior call with the same provider ID (`src/modules/gateway/adapters/gemini.ts:99-105`). Two individually valid chunks with distinct fields can therefore produce a merged argument object larger than the limit. The eight-megabyte stream cap bounds the absolute exposure, but the adapter does not enforce its documented per-call tool-argument boundary before returning the merged object.

Serialize and check the merged candidate before assigning it, then cancel the stream reader on overflow. Add a chunked Gemini fixture that repeats one function-call ID with individually sub-limit fragments whose merged UTF-8 representation exceeds `maxToolArgumentsBytes`.
