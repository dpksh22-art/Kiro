# Durable NEXUS completion across providers, agents, lifecycle, and operations

This change completes the single-node beta surface with provider schema/tool mappings, reconciled model snapshots, bounded agent collaboration, research synthesis, GitHub writes, resource budgets, artifact and account lifecycle, and backup verification. The design consistently derives the owner from the session, keeps retrieved/model content outside authority decisions, and uses SQLite transactions and durable intent rows around most state changes. Several release-critical boundaries still fail under concurrency or adversarial inputs. **Watch for:** **confirmed** provider-specific schemas are sent in forms the Anthropic and OpenAI APIs reject, **confirmed** completed or dispatched provider calls can be released from every budget ledger, **confirmed** concurrent GitHub replays corrupt completed intent state, **confirmed** coordinated backup tampering passes verification, **confirmed** account deletion can finish while model requests still use decrypted credentials, and **likely** same-site cross-origin requests can exercise custom write routes without a CSRF check.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed:** the canonical gateway treats one local JSON Schema subset as wire-compatible with every provider. OpenAI strict tools receive optional properties that strict mode forbids, while Anthropic receives unsupported validation constraints verbatim. Anthropic and Gemini discovery also consumes only the first page, and a stale validation response can reverse a completed disconnect.

**Confirmed:** the agent broker keeps authority in server-side allowlists and owner/run/task/attempt checks, but its accounting boundary is later than its external-effect boundary. A later turn failure, invalid research synthesis, cancellation, deadline, or lease recovery can release provider work that already ran.

**Confirmed:** GitHub writes bind payloads to durable keys and use expected SHAs or remote markers, but the initial `prepared` row is not atomically claimed. Overlapping same-key requests can both POST, and a losing request can overwrite a completed row.

**Confirmed:** whole-account deletion coordinates artifact mutations but does not block new model admissions or abort and drain active chat, research, and agent calls before deleting credentials and reporting completion.

**Confirmed:** restore verification trusts a checksum stored beside the manifest. An editor can change the database, update both public hashes, and pass every check, so the current bundle proves self-consistency rather than authenticity.

**Confirmed:** untrusted source titles and canonical URLs bypass the 48,000-character evidence-packet counter. **Likely:** a nonconforming provider can also exhaust memory because structured output has no incremental byte ceiling before accumulation and parsing.

**Likely:** custom mutating routes authenticate cookies but do not validate `Origin`, Fetch Metadata, a CSRF token, or JSON content type. **Confirmed:** the runtime image also ships development dependencies that the production audit excludes.

<summary>Issues (11)</summary>

1. **Provider schema incompatibility** — **confirmed:** OpenAI strict internal-tool schemas omit optional fields from `required`, and Anthropic receives unsupported constraints unchanged. Normalize and validate schemas per provider before advertising these features.
2. **Completed provider work released from budgets** — **confirmed:** later task, validation, cancellation, deadline, and recovery failures release calls that crossed or completed the provider boundary. Consume model calls at dispatch and settle or conservatively retain post-dispatch usage.
3. **Concurrent GitHub intent corruption** — **confirmed:** same-key callers can both POST and a late failure can move a completed row to failed. Add an atomic operation claim and monotonic terminal-state updates.
4. **Forgeable backup verification** — **confirmed:** anyone who can edit a bundle can recompute its database hash and adjacent manifest checksum. Authenticate the manifest with a separately protected MAC or signature.
5. **Deletion without owner quiescence** — **confirmed:** account deletion can complete while in-flight work still uses decrypted credentials. Block admissions, abort and fence owner work, settle it, and drain it before completion.
6. **Missing CSRF boundary** — **likely:** hostile same-site origins can send simple cookie-authenticated POSTs because custom routes accept JSON without origin or content-type enforcement. Add a shared origin/Fetch Metadata and CSRF policy.
7. **Truncated provider snapshots** — **confirmed:** Anthropic and Gemini pagination is ignored before unseen models are disabled. Reconcile only a complete, bounded multi-page snapshot.
8. **Disconnect overwritten by validation** — **confirmed:** an older validation response can restore `connected` and available-model state after ciphertext was deleted. Fence validation updates to the connection version and state they started from.
9. **Evidence-packet metadata bypass** — **confirmed:** title and canonical-URL bytes are not included in the packet limit. Bound every field and the final serialized packet before dispatch.
10. **Post-allocation output limits** — **likely:** structured text is accumulated and parsed before the one-megabyte limit runs. Enforce incremental stream and frame limits before `JSON.parse`.
11. **Runtime dependencies omitted from audit gate** — **confirmed:** the image copies all development packages, including runtime-used `tsx`, while CI audits with `--omit=dev`. Audit the final image or ship a minimal production dependency set.

## Provider-specific schemas are invalid on the advertised wire contracts

**Confirmed:** the OpenAI-compatible adapter marks every function definition `strict: true` (`src/modules/gateway/adapters/openai-compatible.ts:57-68`), but `agent_message_send` and `delegate_task` leave optional properties out of `required` (`src/modules/agents/tool-broker.ts:29-30`). OpenAI strict function schemas require every property to be required, with optional values represented through nullable types. These internal tools therefore produce a request-level rejection rather than a model tool call. The controlled test checks emitted JSON only (`tests/unit/gateway-tool-mapping.test.ts`). Current contract: https://developers.openai.com/api/docs/guides/function-calling#strict-mode.

**Confirmed:** the local allowlist accepts `minLength`, `maxLength`, `minimum`, and `maximum` (`src/modules/gateway/schema-validation.ts:19-23`), and the research schema uses these constraints (`src/modules/research/service.ts:23-40`). Anthropic receives that schema unchanged as `output_config.format.schema` (`src/modules/gateway/adapters/anthropic.ts:39-49`), although its raw wire contract does not support those constraints. The provider’s SDK removes them during schema transformation; this adapter does not. Selecting Anthropic for the shipped research schema therefore reaches a provider 400. Current contract: https://platform.claude.com/docs/en/build-with-claude/structured-outputs#json-schema-limitations.

Normalize schemas per provider and add rejection fixtures plus a credentialed promotion gate. The report already states that no provider was live-tested (`docs/IMPLEMENTATION_REPORT.md:23-25`).

## Successful and ambiguous provider work falls out of hard budgets

**Confirmed:** every turn remains provisional until the whole agent task returns. A later repeated tool call, turn-limit failure, or subsequent provider error releases all earlier reservations (`src/modules/agents/turn-loop.ts:60-105`), including streams that reached terminal markers and returned usage. Research similarly releases a completed call when local citation checks reject its result (`src/modules/research/service.ts:236-270`); the test explicitly expects `released` (`tests/integration/research-synthesis.test.ts:93-103`).

**Confirmed:** cancellation changes every still-reserved monetary and resource row to `released` before active requests stop or their outcomes are known (`src/modules/agents/service.ts:202-213`); deadline and lease recovery follow the same policy. This contradicts `model_calls` as “one admitted provider request” (`docs/COSTS.md:22-26`) and permits repeated failure or cancellation under hard call, token, and monetary ceilings.

Consume `model_calls` at dispatch, settle terminal turns immediately, and retain conservative or unknown accounting after the provider boundary. Add regressions for successful-first-turn/later-failure, completed invalid research, post-dispatch cancellation, and lease recovery.

## Concurrent GitHub replays are not serialized

**Confirmed:** `prepareOperation` returns an existing `prepared` row without atomically claiming it (`src/modules/github/service.ts:114-142`). Branch, file, and PR implementations treat `prepared` as permission to proceed, while `updateOperation` writes any state using only `WHERE id=?` (`src/modules/github/service.ts:145-150`). Two same-key requests can both cross the write boundary, and a late error can replace `completed` with `failed`.

A targeted branch reproduction synchronized two callers after both observed the target as absent. Both POSTed; one fulfilled and one received 422. The row ended as `state='failed'` with a non-null completed `response_json`. Branch/file compare-and-swap usually prevents duplicate remote state, but the documented “never repost” guarantee fails and PR safety depends on GitHub rejecting the duplicate.

Claim `prepared -> pending` with one conditional update, make followers reconcile or wait, and prevent transitions out of `completed`. Add overlapping branch, file, and draft-PR tests.

## Backup verification has no authenticity root

**Confirmed:** creation writes `manifest.sha256` beside `manifest.json` (`src/core/backup.ts:185-188`), and verification trusts that editable checksum (`src/core/backup.ts:236-241`). Database, artifact, migration, and row-count checks then compare only with the same manifest (`src/core/backup.ts:246-274`).

A targeted reproduction changed the backed-up owner name, recomputed `manifest.database`, `manifest.json`, and `manifest.sha256`, and `verifyBackup` returned `ok: true` with the modified owner. An editor can preserve counts while changing authentication data, trusted memory, or GitHub intent history. The current test modifies artifact bytes without updating the manifest, so it proves accidental-corruption detection only (`tests/integration/backup-restore.test.ts`).

Authenticate the manifest with a key kept separately from the bundle, or sign it against a separately trusted public key. Until then, document this as an unsigned self-consistency check.

## Account deletion can complete while credentials remain active

**Confirmed:** deletion enters only the artifact lock, then deletes the user and marks the job complete (`src/modules/lifecycle/account-deletion.ts:118-160,181-189`). It does not block model admissions, cancel runs, abort chat/research controllers, or wait for provider work. Agent controllers are exposed only by task/run operations (`src/modules/agents/runtime.ts:11,127-158,282-284`), while chat and agent calls have already decrypted credentials at dispatch (`src/modules/workspace/chat.ts:100-104`, `src/modules/agents/turn-loop.ts:75-79`).

A concurrent tab or worker can continue a paid remote request after deletion reports completion. New work can race admission until the cascade commits, and an orphaned worker later returns to a deleted task graph.

Add a durable owner-quiescing state checked by all admissions. Abort and fence active owner work, account for ambiguous usage, and drain it before removing credentials and returning `completed`. Cover chat, research, root-agent, delegated-child, and cancellation races.

## Cookie-authenticated write routes lack a CSRF boundary

**Likely:** `requireApiSession` checks the session but not origin or Fetch Metadata (`src/core/session.ts:15-18`). GitHub write routes parse JSON regardless of `Content-Type` and treat a payload boolean as confirmation (`app/api/v1/github/branches/route.ts:15-21`, `app/api/v1/github/changes/apply/route.ts:8-22`, `app/api/v1/github/pulls/route.ts:5-11`). Run cancellation, disconnect, research spending, and other POST mutations share this pattern.

With an attacker-controlled sibling origin under the same registrable site, `fetch` with `credentials: "include"` and `Content-Type: text/plain` is a simple same-site request; `request.json()` still parses it. Confirm the deployed Better Auth cookie attributes, then require the configured origin and allowed content type through a shared mutation guard, preferably with CSRF-token or strict Fetch Metadata enforcement. Keep `confirm: true` as intent metadata, not an anti-CSRF control.

## Provider reconciliation treats partial or stale responses as authoritative

**Confirmed:** Anthropic makes one `/v1/models` request and consumes only `data` (`src/modules/gateway/adapters/anthropic.ts:28-32`); Gemini likewise consumes one `models` page (`src/modules/gateway/adapters/gemini.ts:32-38`). Both APIs paginate through `has_more`/`last_id` or `nextPageToken`. Reconciliation disables every model before re-enabling this partial result (`src/modules/gateway/connections.ts:66-75`), so later-page models disappear.

**Confirmed:** validation also reads and decrypts a connection, waits for the network, then unconditionally writes `connected` (`src/modules/gateway/connections.ts:60-75`). A concurrent disconnect clears ciphertext and writes `disconnected` (`src/modules/lifecycle/service.ts:8-14`), but the older response can restore connected/available state with no credential, contradicting the documented disconnect result (`docs/SECURITY.md:60-64`).

Follow all cursors under explicit bounds and commit only a complete snapshot. Fence each commit to the credential/version/state that began validation, and leave an incomplete snapshot degraded rather than authoritative. Test two-page discovery, second-page failure, out-of-order validations, and disconnect during validation.

## The evidence-packet limit excludes untrusted metadata

**Confirmed:** HTML titles and canonical links have no field limit (`src/modules/research/connectors.ts:11-16,26-29`). Packet construction includes the complete title and URL but increments its 48,000-character budget only by excerpt length (`src/modules/research/service.ts:15-18,96-104`). Up to 20 source responses can therefore create a packet far larger than advertised, increasing memory, provider context/cost, and adversarial prompt content.

Bound every serialized field, require canonical URLs to remain HTTP(S), and enforce the final packet byte size before reservation and dispatch. Add oversized title/canonical and aggregate-source tests. The current README calls these packets bounded (`README.md:23-26`).

## Structured-output limits run after allocation and parsing

**Likely:** all three adapters append every text delta without an incremental byte limit (`src/modules/gateway/adapters/anthropic.ts:89-117`, `src/modules/gateway/adapters/gemini.ts:75-100`, `src/modules/gateway/adapters/openai-compatible.ts:91-117`). `parseStructuredOutput` calls `JSON.parse` first (`src/modules/gateway/mapping.ts:66-74`); only then does `assertBoundedOutput` enforce one megabyte and node/depth limits (`src/modules/gateway/schema-validation.ts:107-135`). A compromised or nonconforming provider, including an operator-configured compatible endpoint, can force large string and parser allocation before the local ceiling executes.

Count bytes while streaming, bound SSE frames, and reject before parsing. Test chunked oversized output rather than only an already-materialized object.

## The runtime image audit excludes shipped packages

**Confirmed:** the runtime image copies the build stage’s full `node_modules` (`Dockerfile:20-24`). Production startup, backup, and restore use `tsx`, which is a development dependency (`package.json:14,22-24,46-49`), while CI runs only `npm audit --omit=dev` (`.github/workflows/ci.yml:30-33`). Future vulnerabilities in shipped executable packages will not fail that gate.

Ship a minimal runtime dependency set, move actual runtime tools into production dependencies or compile them, and audit/scan the final image. Full `npm audit` currently also reports zero findings, so no known vulnerable package was found.

## Passing checks miss the blocking behaviors

The configured build completed 39 work items; lint, typecheck, 121 tests in 24 files, persistence restart, production smoke, five Chromium scenarios, `npm audit --omit=dev`, and full `npm audit` passed. The container could not run because this sandbox has no working `conmon`, matching the documented limitation.

**Confirmed:** provider tests inspect mocked shapes rather than rejecting wire contracts; the research test asserts released completed usage; GitHub tests are sequential; backup tampering does not recompute the manifest; account deletion has no active-work fixture; CSRF has no hostile-origin scenario; and packet/output tests begin after oversized values are materialized. Add focused regressions for each issue above.
