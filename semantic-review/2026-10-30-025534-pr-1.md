# Strict provider schemas and composed outbound cancellation

This final follow-up rejects OpenAI strict schemas whose openness or composition cannot be represented faithfully, while retaining direct optional-field normalization and exact canonical validation. It also composes owner aborts with fixed GitHub and research deadlines, and the focused provider, research, signal, and GitHub suites pass. A **confirmed, high** partial-retrieval race can still cross the evidence and budget boundaries after caller cancellation; **confirmed, medium** GitHub route requests still do not supply a caller signal.

**Watch for:** **confirmed, high** a cancelled multi-source research request can persist partial evidence and conservatively consume a synthesis reservation; **confirmed, medium** GitHub caller cancellation is absent at every route/service entry point, so disconnected requests can continue using the owner token until completion or the 20-second deadline.

**Verdict**: NEEDS_CHANGES

## High-level view

OpenAI strict-mode translation now rejects non-false `additionalProperties` and schema combinators before fetch, preserving the distinction between direct optional fields and explicitly nullable fields.

**Confirmed, high:** research composes owner and caller signals, but `Promise.allSettled` treats cancellation like a per-source failure. One completed source lets an aborted request persist evidence and reserve synthesis usage.

**Confirmed, medium:** GitHub combines owner aborts with its 20-second deadline, but route handlers and exported services expose no caller signal. Browser disconnects do not reach reads, preflight checks, writes, or reconciliation.

## Partial retrieval converts caller cancellation into persisted evidence and charged unknown usage

**Confirmed, high:** connector retrieval uses `Promise.allSettled` with the composed signal, then immediately collects fulfilled items and stores them (`src/modules/research/service.ts:232-242`). There is no `admissionSignal.aborted` or `throwIfAborted()` check between retrieval settlement and persistence. In a two-source request where one connector finishes before cancellation and another rejects because of cancellation, `items.length` remains nonzero, so the source and report transactions run despite the caller having withdrawn the request.

With a synthesis target, the same path continues to `reserveUsage` and enters the adapter with the already-aborted signal (`src/modules/research/service.ts:271-293`). Every adapter invokes `onDispatch` before calling `fetch`; the aborted fetch then fails and `releaseUsage` conservatively settles the reservation as unknown. This consumes estimated tokens and cost even though the request should have stopped before evidence persistence and model admission. The new cancellation test uses only one hanging connector, which guarantees zero fulfilled items and therefore does not exercise this branch.

Check the composed signal immediately after `Promise.allSettled` and before normalizing or storing any retrieved item, and check it again before model reservation. Add a synchronized fixture with one fulfilled source and one aborting source; assert that no research source, report, usage row, or provider call is created.

## GitHub signal composition has no caller signal to compose

**Confirmed, medium:** `api` correctly calls `boundedSignal(20_000, githubOperationSignal.getStore(), init.signal)`, but every exported operation accepts only `userId`, repository data, and the operation payload (`src/modules/github/service.ts:602-606`). The branch, file, and pull-request routes call those exports without `request.signal` (`app/api/v1/github/branches/route.ts:21`, `app/api/v1/github/changes/apply/route.ts:20`, `app/api/v1/github/pulls/route.ts:11`); the read routes have the same omission. Consequently, `init.signal` is unset in normal route traffic and the composed signal contains only owner cancellation plus the deadline.

The 20-second bound prevents the unbounded wait from the prior pass, but a disconnected request can still retain a decrypted token and continue a remote read or write. Add an optional caller signal at the exported service boundary, pass `request.signal` from every GitHub route, and preserve durable write reconciliation when cancellation makes a dispatched outcome ambiguous. Cover cancellation during a preflight read and during a write with assertions that the reader aborts, no second POST occurs, and the intent remains monotonic.
