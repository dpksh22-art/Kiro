## Non-global IPv6 prefixes still pass research admission

**High blocker, confirmed.** `isPrivateIp` considers an address safe whenever `ipaddr.process(address).range()` returns `unicast` (`src/modules/research/http.ts:9-15`). That label is the library's fallback category, not an IANA global-reachability decision. The current dependency classifies `64:ff9b:1::/48` and `3fff::/20` as `unicast`; direct calls to `assertPublicUrl` accepted both prefixes. The local-use translation prefix is especially important because addresses such as `64:ff9b:1::7f00:1` and `64:ff9b:1::a9fe:a9fe` embed loopback and link-local IPv4 destinations and can be routed by a host or network using RFC 8215 local-use NAT64.

Pinning does not contain this gap because `validatedAddresses` passes the admitted literal address directly to the pinned Undici dispatcher (`src/modules/research/http.ts:18-27`, `36-49`). Replace the fallback-range test with an allowlist derived from the current IANA special-purpose registries, or explicitly reject every non-global prefix before pinning. Add regression cases for `64:ff9b:1::/48`, `3fff::/20`, and future registry additions instead of treating `unicast` as equivalent to public.
