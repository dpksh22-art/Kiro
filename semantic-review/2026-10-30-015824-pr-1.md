# Safe whole-account deletion with retryable byte cleanup

The change adds a password-confirmed owner deletion flow that removes content-addressed bytes before cascading the owner’s SQLite data, while retaining a credential-free job tombstone and redacted audit evidence. Filesystem failures and pre-transaction crashes remain retryable, and concurrent same-key replays preserve completed tombstones. A replacement owner can recover from a completed key left in the same browser without weakening same-owner retries. **Watch for:** no blocking concerns remain.

**Verdict**: APPROVED

## High-level view

The lifecycle service runs byte cleanup under the artifact mutation/snapshot lock and finalizes deletion in one SQLite transaction only after every recorded path is absent. Path validation rejects malformed content-addressed metadata, non-files, symlinks, and resolved parents outside the configured artifact root. Failure before finalization keeps the owner and retry job intact.

The HTTP route derives identity only from the active session, rejects extra request fields, verifies the current password through Better Auth, and requires the exact phrase plus a UUID idempotency key. The Settings flow preserves that key across ambiguous failures, rotates it only for the completed-prior-owner conflict, warns that local ciphertext deletion does not revoke remote credentials, and redirects only after completion.

The migration command disables Better Auth schema validation only on its dedicated migration instance. Production request initialization keeps validation enabled, and the clean-start regression reaches `0009_account_deletion.sql` without the transient schema-mismatch diagnostic.

The prior concurrent-replay, replacement-owner key, browser selector, and stale verification-record findings are resolved. The final recorded matrix covers migration, lint, type checking, 121 tests in 24 files, a 39-work-item build, five Chromium tests, production and persistence smoke tests, and a zero-finding production dependency audit. A focused review rerun passed six deletion and migration tests in three files.

## Completed tombstones survive serialized replays

The cleanup lock re-reads the job after a queued request enters the serialized section. A request following a successful peer returns the completed result instead of changing the tombstone back to `deleting_files`; the outer catch also preserves completion. The integration test issues two concurrent calls with one owner and key, requires both to complete, and verifies the retained row has a completion timestamp and no error.

Filesystem work remains outside the final transaction so bytes disappear before database ownership. The transaction verifies no path remains pending, removes explicit RESTRICT joins, redacts historical audit metadata, writes the deletion event, deletes the owner, checks authentication rows and foreign keys, marks the job completed, and removes path-level recovery rows.

Relevant code: `src/modules/artifacts/service.ts`, `src/modules/lifecycle/account-deletion.ts`, `tests/integration/account-deletion.test.ts`.

## Session-bound deletion preserves retry ownership

The route accepts only password, exact confirmation phrase, and UUID key. The owner comes from `requireApiSession`, and Better Auth receives the original headers for password verification. Session validation remains the first gate, so a deleted session cannot query a completed tombstone.

Completed keys remain globally unique. When a replacement owner’s browser carries a prior owner’s key, the service returns `stale_completed_idempotency_key`; the form creates one new UUID and reposts once. Other conflicts and transient failures retain the current key. Provider and GitHub ciphertext disappears locally through the cascade, while the UI and documentation explicitly require issuer-side credential revocation before deletion.

Relevant code: `app/api/v1/account/delete/route.ts`, `components/account-deletion-form.tsx`, `db/migrations/0009_account_deletion.sql`, `tests/unit/account-deletion-route.test.ts`, `tests/e2e/workspace.spec.ts`.
