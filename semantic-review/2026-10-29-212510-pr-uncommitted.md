# NEXUS AI OS final beta-boundary remediation

The current remediation closes the prior single-owner, SSRF, budget-scope, GitHub issue idempotency, standalone startup, and readiness-migration findings. Provider, project, and task budget selection now behaves as scoped, and operators can attach sourced pricing to owned models. Two durability guarantees remain unsafe under worker loss: run deadlines are not evaluated while model calls are active, and successful task state can commit before its reservation is settled. Attempt history and currency handling also remain inconsistent with the advertised hard boundaries, while the automated release gate omits several repaired paths.

Watch for: **confirmed blockers** — active provider calls suppress scheduled run-deadline checks, and a crash after task success but before usage settlement permanently strands the reservation; **confirmed high concerns** — retryable failures complete attempts as `retry_wait`, monetary policies aggregate arbitrary currencies as one unit, and CI does not run the standalone smoke or hard-boundary regressions.

**Verdict**: NEEDS_CHANGES

## High-level view

The database trigger now enforces one owner even when concurrent requests pass the bootstrap precheck. Research URL admission rejects every `ipaddr.js` non-unicast range, validates all DNS answers, and pins the accepted set into Undici for each redirect hop.

Global policies now omit provider filtering, provider policies retain it, project policies require an owned project, and per-task policies use task or answer identity. The documented pricing form and owned update route provide a manual evidence path. **Confirmed high concern:** policies are entered as dollars but pricing accepts any ISO currency, and the spend query sums records without a currency predicate or conversion.

Expired active and cancelled leases now release task-linked reservations and mark recovered attempts `abandoned` or `cancelled`. **Confirmed blocker:** successful task and attempt state commits before `settleUsage`, leaving no recovery path if the process dies in that gap.

Run and per-agent timeout failures use `deadline_exceeded`. **Confirmed blocker:** the only run-deadline scan is inside a polling cycle that remains locked until every claimed provider call returns, so an active call can outlive the run deadline. **Confirmed high concern:** an ordinary retryable execution failure still records the completed attempt as `retry_wait` rather than a terminal attempt result.

Pending GitHub issue operations now reconcile their marker before any repost, and the browser retains one UUID until success. The migration-first standalone server and latest-migration readiness probe passed directly. **Confirmed high concern:** CI does not invoke that production smoke and the checked-in suites still omit most concurrency, crash-window, pinning, deadline, and idempotency cases.

<summary>Details</summary>

## Run deadlines wait behind active provider calls

**Blocker, confirmed.** `workerTick` returns whenever `polling` is already true, calls `expireRunDeadlines` only at the beginning of a cycle, and then holds `polling=true` while awaiting all claimed executions (`src/modules/agents/runtime.ts:207-223`). The one-second embedded timer therefore cannot run another deadline scan while a provider request is active. A focused reproduction created a 200 ms run deadline around a non-returning provider request and repeatedly invoked the scheduler: the run was still `running` 700 ms after its deadline, then changed to `failed` with `deadline_exceeded` only when `expireRunDeadlines` was called directly. Enforce the run deadline with an abort timer attached to each claim, using the earlier of the run and agent deadlines, or move deadline recovery to a scheduler that does not share the execution polling guard.

## Successful task state can commit without budget settlement

**Blocker, confirmed.** The success transaction commits the task as `succeeded` and the attempt as `succeeded`, then calls `settleUsage` afterward (`src/modules/agents/runtime.ts:155-166`). A process loss between those operations leaves a `reserved` record attached to terminal work. `recoverExpired` only scans leased, running, and cancellation-requested tasks, so it cannot repair that state (`src/modules/agents/runtime.ts:18-33`). A focused database reproduction of this exact post-commit state remained `reserved` after recovery. Settle the linked reservation in the same fenced transaction that commits task and attempt success; keep expired-lease release in the recovery transaction for pre-completion crashes.

## Retryable failure is stored as an attempt state

**High, confirmed.** The failure path derives one `status` value and writes it to both the task and its completed attempt (`src/modules/agents/runtime.ts:171-180`). When another attempt is allowed, both receive `retry_wait`; the attempt also receives `completed_at`. A focused provider-failure run produced `{ status: "retry_wait", completedAt: ..., errorCode: "execution_failed" }` in `task_attempts`. Keep `retry_wait` on the task while recording the finished attempt as a terminal value such as `failed` or `retryable_failed`.

## Monetary limits combine currencies without conversion

**High, confirmed.** Budget creation names the amount `hardLimitDollars` and stores dollar micros (`app/api/v1/budgets/route.ts:17-30`), while model pricing accepts any three-letter currency (`app/api/v1/models/[id]/pricing/route.ts:9-17`). Admission sums `billed_cost_micros` or `estimated_cost_micros` without filtering by currency (`src/modules/gateway/budgets.ts:38-40`), and chat reservations do not copy the model currency at all (`src/modules/workspace/chat.ts:64`). Global and project budgets can therefore combine USD, EUR, GBP, or provider-reported costs as though their micros were interchangeable, allowing under-enforcement or false denial. Constrain the beta to USD end to end, including settlement validation, or add policy currency plus an attributable conversion mechanism.

## Release checks omit repaired hard boundaries

**High, confirmed.** The configured clean-database `npm run check` passed lint, typechecking, 22 unit/integration assertions, and the production build; all three browser tests, the standalone production smoke, and `npm audit --omit=dev` also passed. The checked-in CI runs unit/integration, build, and browser suites but never runs `npm run test:production` (`.github/workflows/ci.yml:33-46`); among the remediated budget and recovery boundaries, current tests cover only global aggregation and expired-cancel recovery. There are no automated cases for concurrent owner insertion, pinned connection dispatch, provider/project/task budget combinations, post-success reservation recovery, run-deadline scheduling, retry-attempt terminal status, or GitHub pending reconciliation. Add these cases and the standalone smoke to CI before treating the repaired boundaries as a beta release gate; update `docs/TESTING.md`, whose final verification entries still say rerun required.
